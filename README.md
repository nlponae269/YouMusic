# YouMusic

Музыкальный стриминг под Yandex Cloud: PWA-плеер с «живым» фоном под цвет обложки, волной-прогрессом, синхронным текстом песен, лайками, плейлистами и голосовым поиском.

## Возможности

- **Плеер**: большая обложка со свечением, волна-прогресс (перемотка тапом/свайпом), shuffle, повтор (очередь/трек), громкость, скачивание трека.
- **Цвета под трек**: фон, акцент, бегущая строка и кнопки перекрашиваются под обложку текущего трека.
- **Подборки**: «Моя волна» (подстраивается под лайки), «Новинки», «В тренде», «Любимое». Обновляются раз в час.
- **Текст песни**: обычный или LRC с таймкодами — строки подсвечиваются в такт, тап по строке перематывает.
- **Любимое и плейлисты**: привязаны к устройству (анонимный ID, без регистрации).
- **Поиск** по названию/артисту/альбому + **голосовой поиск** (Web Speech API).
- **Экран блокировки**: управление через Media Session API, работает в фоне.
- **PWA**: можно установить на главный экран телефона.
- **Админка** `/admin.html`: перетащите пачку файлов — теги ID3, обложка и текст подтянутся сами, волна и цвет обложки посчитаются в браузере. Файлы идут напрямую в Object Storage по подписанным ссылкам, минуя сервер.

## Архитектура

```
Браузер ──► Serverless Container (Node.js, Express) ──► Managed PostgreSQL (каталог, лайки, плейлисты)
   │                     │
   │                     └─ подписывает ссылки ─┐
   └──── аудио (HTTP Range), загрузка ─────────►  Object Storage (mp3/flac/…, обложки)
```

Сервер не прокачивает аудио через себя: `/api/tracks/:id/stream` отвечает редиректом на подписанную ссылку Object Storage, поэтому перемотка работает нативно, а контейнер почти не нагружается.

## Деплой в Yandex Cloud

Нужно: [yc CLI](https://yandex.cloud/ru/docs/cli/quickstart) (выполнен `yc init`), Docker, `jq`, Node.js 20+.

```bash
SEED=1 ./deploy/yandex-cloud.sh
```

Скрипт создаст (или переиспользует) сервисный аккаунт со статическим ключом, бакет, кластер PostgreSQL (s2.micro, ~10 минут при первом запуске), реестр, соберёт образ и выкатит ревизию Serverless Container с публичным доступом. В конце выведет адрес приложения и `ADMIN_TOKEN`. `SEED=1` добавит 6 синтезированных демо-треков, чтобы было что послушать сразу.

Повторный запуск = выкатка новой версии. Секреты лежат в `deploy/.state.env` (в git не попадает).

Хотите свой домен — подключите API Gateway или Certificate Manager к контейнеру и запустите `node scripts/setup-bucket.js https://ваш-домен`, чтобы разрешить загрузку с него в CORS бакета.

## Локальный запуск

```bash
docker compose up --build              # приложение + PostgreSQL + MinIO
docker compose exec app npm run seed   # демо-треки
```

Откройте http://localhost:8080, админка — http://localhost:8080/admin.html (токен `change-me`, переопределяется через `ADMIN_TOKEN`).

Без Docker: заполните `.env` по образцу `.env.example` и выполните `npm install && npm run setup-bucket && npm run dev`.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `DATABASE_URL` | строка подключения к PostgreSQL |
| `PGSSLROOTCERT` | путь к CA Яндекса (в Docker-образе уже есть) |
| `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | бакет и статический ключ |
| `S3_ENDPOINT` | по умолчанию `https://storage.yandexcloud.net` |
| `S3_PUBLIC_ENDPOINT` | адрес хранилища для браузера, если отличается (локальный MinIO) |
| `S3_FORCE_PATH_STYLE` | `true` для MinIO |
| `ADMIN_TOKEN` | пароль админки |
| `PORT` | порт, по умолчанию 8080 (Serverless Containers задают сами) |

## Тексты песен

В админке можно вставить обычный текст или LRC:

```
[00:12.40] Город гасит окна по одному
[00:17.85] Мы ловим ритм на пустом шоссе
```

## Важно

Загружайте только музыку, на которую у вас есть права, — стриминг чужих треков без лицензии нарушает авторские права.
